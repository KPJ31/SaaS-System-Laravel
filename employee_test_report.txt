Bugs found
- Activity History search used an ungrouped orWhere that could bypass the own-user filter for matching action values.
- Stop Work updated the WorkSession outside a transaction, leaving a race risk for double-click or concurrent stop requests.
- Employee Task, Document, and Work Session filters accepted arbitrary project/task IDs instead of rejecting IDs outside the Employee's assigned work.
- Employee file downloads did not check that the file still existed before returning a download response.
- Employee personal CSV exports did not protect formula-like cells.
- Leave update/cancel actions did not create activity logs.

Root causes
- Several base queries were correctly scoped, but request-supplied filter IDs were not separately authorized.
- A search closure used orWhere without grouping.
- CSV writers used raw fputcsv values.
- Timer start used a transaction and lock, while timer stop did not.
- Leave self-service actions updated data without audit logging.

Bugs fixed
- Grouped Employee activity search conditions to preserve own-user and company scope.
- Wrapped WorkTimerService::stop in a database transaction with row locking.
- Added Employee task project-filter authorization.
- Added Employee document project/task filter authorization.
- Added Employee work-session project/task filter authorization.
- Added missing-file 404 handling for Employee file downloads.
- Added company check to task assignment inside Employee file download authorization.
- Added CSV formula-injection protection to Employee work-session and attendance exports.
- Added audit logs for pending leave updates and cancellations.
